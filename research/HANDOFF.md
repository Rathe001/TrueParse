**Your task: wire the Notes view into the MoP Classic client.** It works on
retail. On MoP Classic it does not exist at all — `TrueParse_Mists.toc` loads
no `Notes\` files, so there is no view to toggle to. Five pieces:

1. TOC entries in `TrueParse_Mists.toc`.
2. **A Mists capability table.** `Notes/Classes.lua` is retail-only: it
   encodes Midnight's healer-interrupt removals, Evoker and Demon Hunter rows,

3. **A no-affix, no-keystone header.** MoP has Challenge Modes, not Mythic+.
   (Difficulty id 8 is Challenge Mode in MoP and already maps to `"k"`, which
   happens to be right.)
4. **`Notes/Mists.lua`**, registering MoP content from
   `research/instances/mists-*.md` — 9 dungeons and 5 raids, ~80 bosses,
   already researched and reconciled into the field shape `Season2.lua` uses.
5. **`Notes/Season2.lua` must NOT load on Mists** — it registers 8 retail

**Gotchas that will cost you time:**

- `tests/notes.lua` test 6 leaves an `as tank` override active, and
  `Player.Caps()` answers from the override rather than the current spec. Any
  capability assertion after that point silently reads the wrong spec unless
  it clears the override first.
- `pcall(C_Namespace.Fn, x)` indexes the namespace **before** pcall runs, so a
  nil namespace errors outside the pcall. MoP Classic lacks
  `C_EncounterJournal`; one such crash is already fixed in `Notes/Journal.lua`
  but the pattern recurs.
- The instance registry is keyed by **journal instanceID, not name**. Two
  instances may share a name only if both declare `instanceID`; registration
  errors loudly otherwise. This exists because Midnight ships a dungeon called
  Magisters' Terrace and the TBC Timewalking pool contains a different one
  with the same name. Do not "fix" it by falling back to names.
- `RegisterRaid` deliberately **errors** on a `trash` table. Raids are
  boss-only by decision, and that also dissolves the parallel-wing ordering
  problem.

**Three open design questions in `INVENTORY.md`** — read them before
